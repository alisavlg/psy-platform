# PsyHelp — API

## 1. Что такое API

**API (Application Programming Interface)** — это «язык общения» между фронтендом (сайт) и бэкендом (сервер).

**Аналогия:**
Вы (фронтенд) приходите в ресторан. Официант (API) принимает заказ, передаёт на кухню (бэкенд), приносит блюдо (ответ). Вы не ходите на кухню сами — вы общаетесь через официанта.

**Зачем нужно API:**
- Фронтенд не знает, как устроена база данных.
- Бэкенд не знает, как выглядит сайт.
- Они общаются через **чёткие правила** — это и есть API.

---

## 2. Как выглядит запрос

**Структура:**
- МЕТОД — что делаем (GET, POST, PUT, PATCH, DELETE)
- /адрес — куда обращаемся
- Заголовки (Headers) — кто мы (токен авторизации)
- Тело (Body) — данные (если есть)

**Пример:**

```
POST /api/auth/register
Content-Type: application/json

{
  "email": "anna@example.com",
  "password": "secret123",
  "firstName": "Анна",
  "middleName": "Сергеевна",
  "lastName": "Иванова",
  "phone": "+79001234567"
}
```

**Ответ:**

```
200 OK
Content-Type: application/json

{
  "success": true,
  "userId": 42,
  "message": "Регистрация успешна. Проверьте email."
}
```

---

## 3. Методы HTTP

| Метод | Что делает | Пример |
|-------|------------|--------|
| **GET** | Получить данные | `GET /api/psychologists` |
| **POST** | Создать | `POST /api/sessions` |
| **PUT** | Обновить полностью | `PUT /api/users/42` |
| **PATCH** | Обновить частично | `PATCH /api/users/42` |
| **DELETE** | Удалить | `DELETE /api/sessions/15` |

---

## 4. Коды ответов

| Код | Значение |
|-----|----------|
| **200** | OK — всё хорошо |
| **201** | Created — создано |
| **400** | Bad Request — ошибка в запросе |
| **401** | Unauthorized — не авторизован |
| **403** | Forbidden — нет прав |
| **404** | Not Found — не найдено |
| **500** | Server Error — ошибка сервера |

---

## 5. Авторизация

После входа сервер выдаёт **токен** (JWT). Фронтенд сохраняет его и прикрепляет к каждому запросу:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

Сервер проверяет токен и понимает: «Это пользователь с ID 42, у него роли client, psychologist».

## 6. Структура API (обзор)

```
/api
├── /auth           ← регистрация, вход, восстановление пароля
├── /users          ← профиль пользователя
├── /psychologists  ← психологи
├── /sessions       ← сессии
├── /events         ← календарь
├── /payments       ← платежи
├── /tasks          ← задачи (делегирование)
├── /admin          ← админ-функции
├── /chats          ← чаты (этап 2)
├── /articles       ← блог (этап 2)
└── /questions      ← Q&A (этап 2)
```

---

## 7. Правила отображения имени

- **Публично показываем:** имя + отчество (например, «Анна Сергеевна»).
- **Фамилия** хранится в базе, но **не показывается** публично.
- **Обращение** на сессии — по имени или имени-отчеству — клиент и психолог решают сами.
- **В системе** пользователи не определяются по фамилии.

## 8. MVP API: Аутентификация

### 8.1. Регистрация

**Эндпоинт:**

```
POST /api/auth/register
```

**Тело запроса:**

```json
{
  "email": "anna@example.com",
  "password": "secret123",
  "firstName": "Анна",
  "middleName": "Сергеевна",
  "lastName": "Иванова",
  "phone": "+79001234567",
  "timezone": "Europe/Moscow"
}
```

**Правила:**
- Email — уникальный, валидный.
- Пароль — минимум 8 символов, хотя бы одна буква и одна цифра.
- Имя, отчество, фамилия — обязательные, минимум 2 символа.
- Телефон — валидный, уникальный.
- Часовой пояс — обязательный (для календаря).

**Ответ (200):**

```json
{
  "success": true,
  "userId": 42,
  "message": "Регистрация успешна. Проверьте email и телефон."
}
```

**Что происходит на сервере:**
1. Создаётся запись в `users` (email, password_hash, first_name, middle_name, last_name, phone, timezone).
2. Назначается роль `client` (запись в `user_roles`).
3. Генерируется токен подтверждения email → отправляется письмо.
4. Генерируется код подтверждения телефона (SMS).
5. Статус: `is_email_confirmed = false`, `is_phone_confirmed = false`.

**Ошибки:**

| Код | Причина |
|-----|---------|
| 400 | Невалидные данные |
| 409 | Email или телефон уже заняты |

---

### 8.2. Подтверждение email

**Эндпоинт:**

```
GET /api/auth/confirm-email?token=xxx
```

**Что делает:** проверяет токен из письма, ставит `is_email_confirmed = true`.

**Ответ (200):**

```json
{
  "success": true,
  "message": "Email подтверждён."
}
```

**Ошибки:**

| Код | Причина |
|-----|---------|
| 400 | Токен невалиден или истёк |

---

**Ответ (200):**


**Ошибки:**

### 8.6. Вход

**Эндпоинт:**

```
POST /api/auth/login
```

**Тело:**

```json
{
  "email": "anna@example.com",
  "password": "secret123"
}
```

**Ответ (200):**

```json
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": 42,
    "firstName": "Анна",
    "middleName": "Сергеевна",
    "roles": ["client"]
  }
}
```

**Правила:**
- Пользователь должен подтвердить email и телефон.
- Если email не подтверждён — ошибка 403 с сообщением «Подтвердите email».
- Если телефон не подтверждён — ошибка 403 с сообщением «Подтвердите телефон».

**Ошибки:**

| Код | Причина |
|-----|---------|
| 400 | Невалидные данные |
| 401 | Неверный email или пароль |
| 403 | Email или телефон не подтверждён |

---

### 8.7. Выход

**Эндпоинт:**

```
POST /api/auth/logout
```

**Что делает:** удаляет токен из чёрного списка (если используется JWT-блэклист) или просто стирает его на фронтенде.

**Ответ (200):**

```json
{ "success": true, "message": "Вы вышли из системы." }
```

---

### 8.8. Восстановление пароля — запрос

**Эндпоинт:**

```
POST /api/auth/forgot-password
```

**Тело:**

```json
{ "email": "anna@example.com" }
```

**Что делает:** генерирует токен восстановления, отправляет письмо со ссылкой.

**Ответ (200):**

```json
{ "success": true, "message": "Письмо отправлено." }
```

**Важно:** даже если email не найден, ответ всё равно 200 — чтобы не раскрывать, есть ли такой пользователь.

---

### 8.9. Восстановление пароля — сброс

**Эндпоинт:**


**Тело:**

```json

  "token": "xxx",

```

**Что делает:** проверяет токен, обновляет `password_hash`.

**Ответ (200):**

```json

```

**Ошибки:**

| Код | Причина |
|-----|---------|
| 400 | Токен невалиден или истёк |
| 400 | Пароль не соответствует правилам |

### 8.10. Проверка токена (для фронтенда)

**Эндпоинт:**

```
GET /api/auth/me
```

**Заголовок:** `Authorization: Bearer xxx`

**Ответ (200):**

```json
{
  "id": 42,
  "firstName": "Анна",
  "middleName": "Сергеевна",
  "lastName": "Иванова",
  "email": "anna@example.com",
  "phone": "+79001234567",
  "timezone": "Europe/Moscow",
  "roles": ["client"],
  "isEmailConfirmed": true,
  "isPhoneConfirmed": true
}
```

**Ошибки:**

| Код | Причина |
|-----|---------|
| 401 | Токен невалиден или истёк |

**Зачем:** фронтенд при загрузке страницы проверяет — авторизован ли пользователь, и какие у него роли.
