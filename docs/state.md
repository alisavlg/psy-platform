## Что дальше (план)

### Этап 1. Прототип (localStorage) — продолжение

1. **Уведомления в интерфейсе.**
   Бейдж и список. При изменении статуса заявки / сессии — новое уведомление.

2. **Отзыв после сессии.**
   Психолог отмечает сессию «проведена» → клиент видит форму отзыва → пишет оценку и текст → попадает в профиль психолога.

3. **Мессенджер — открытие по `?chat=`.**
   Кнопка «Написать» в профиле психолога → `client.html?section=messages&chat=X` → открывается нужный диалог.

4. **Заглушки для форс-мажора.**
   Кнопка «Сообщить о проблеме» в сессии → чат с поддержкой.

5. **Обновление документов.**
   - `database.md`: исправить `users.role` → M:N (`user_roles`), добавить таблицу `applications`.
   - `api.md`: добавить эндпоинт `/applications`.
   - `roles.md`: дополнить поля чек-листа в `tasks`.

### Этап 2. Прототип «для показа»

Дать 2–3 коллегам-психологам и знакомым. Собрать обратную связь. Правки.

### Этап 3. Backend (Supabase)

Переезд на реальную базу. Логика фронтенда не меняется, только хранилище.

### Этап 4. Запуск

Реальные пользователи, реальные деньги.

## Соглашения

1. **Ключи localStorage** — по `user.id`, не по роли (см. `architecture.md`).
2. **CSS** — только через переменные из `theme.css` (см. `theme-guide.md`).
3. **Логика** — сначала отлаживаем на localStorage, потом переносим на API.
4. **UI** — единый минималистичный стиль, приглушённые цвета.
