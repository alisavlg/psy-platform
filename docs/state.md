## Принципы проекта

1. Сначала удобно и функционально — потом реклама.
2. Комфортно и психологу, и собственнику (по бюджету).
3. Если продукт хорош — люди приходят сами.
4. Не бежать впереди паровоза.
5. Хочу получать результат — это нормально, но не в ущерб качеству.
6. Один человек = один набор данных (ключи по user.id, не по роли).
7. Один код — одно место (не дублировать).
8. Сначала уточняем логику — потом пишем код.

## Что дальше (план)

### Этап 1. Прототип (localStorage) — финал

1. **Прогнать полный сценарий пользователя.**
   - Клиент бронирует → уведомления → отмена → возврат.
   - Психолог отмечает «Проведена» → клиент оставляет отзыв → рейтинг обновляется.
   - Слоты: открытие, занятие, отмена, возврат в свободные.

2. **Мелкие UX-правки** — по результатам прогона.

### Этап 2. Прототип «для показа»

Дать 2–3 коллегам-психологам и знакомым. Собрать обратную связь. Правки.

### Этап 3. Backend (Supabase)

Переезд на реальную базу. Логика фронтенда не меняется, только хранилище.

### Этап 4. Запуск

Реальные пользователи, реальные деньги, реальная оплата.

## Известные ограничения прототипа

| Ограничение | Когда решится |
|-------------|---------------|
| Данные в одном браузере | После backend |
| Оплата — заглушка | После ЮKassa |
| Видеосессии — заглушка | После LiveKit / WebRTC |
| Мессенджер не работает между устройствами | После backend |
| Уведомления только в интерфейсе | После email/SMS |
| Демо-психологи вымышленные | Заменятся на реальных |

## Соглашения

1. **Ключи localStorage** — по `user.id`, не по роли.
2. **CSS** — только через переменные из `theme.css`.
3. **Логика** — сначала отлаживаем на localStorage, потом переносим на API.
4. **UI** — единый минималистичный стиль, приглушённые цвета.
5. **Один код — одно место.** Никаких дублей.
6. **Сначала логика — потом код.** Уточняем требования, потом пишем.
